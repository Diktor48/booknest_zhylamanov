# BookNest

Учебный проект по курсу «Современные веб-технологии» (WEB 3210). Каждая лабораторная продолжает предыдущую: HTML → CSS → JavaScript → внешний REST API.

Текущая версия — ЛР 4. Реализации предыдущих этапов сохранены в отдельных ветках; ниже описано, что было сделано на каждом этапе.

## Запуск

Открыть папку проекта в VS Code и запустить `index.html` через Live Server. Либо из папки проекта:

```sh
python -m http.server 5500
```

Адрес: http://localhost:5500/index.html. Для ESM-модулей нужен локальный HTTP-сервер; открытие HTML через `file://` не подходит. Backend для этой лабы не нужен.

## Проверка JavaScript

```sh
npm ci
npm run lint
```

Используется базовая конфигурация ESLint. Если преподаватель выдаст свою, нужно применить её и повторить проверку.

## ЛР 1 — Семантическая разметка

Ветка: [`lab-1/markup`](https://github.com/Diktor48/booknest_zhylamanov/tree/lab-1/markup).

- Три страницы без CSS: каталог (`index.html`), карточка книги (`book.html`), форма выдачи (`loan.html`).
- В каталоге шесть книг, навигация и форма поиска, выбора жанра, сортировки и доступности.
- В карточке — обложка, характеристики через `dl`, описание, отзывы, форма отзыва, похожие книги и хлебные крошки.
- В форме выдачи — поля разных типов, группы `fieldset`/`legend`, подписи `label` и нативная валидация.
- Семантические элементы, один `h1` на страницу, русский язык документа, кодировка, viewport и размеры изображений.

Как проверить: открыть три страницы, пройти ссылки и формы клавиатурой, попробовать отправить незаполненные обязательные поля. Отчёты W3C Validator и Lighthouse сохранены в [`docs/lab1/`](docs/lab1/).

## ЛР 2 — Адаптивная вёрстка и дизайн-токены

Ветка: [`lab-2/styles`](https://github.com/Diktor48/booknest_zhylamanov/tree/lab-2/styles).

- Четыре файла CSS: `tokens.css`, `base.css`, `layout.css`, `components.css`.
- Токены цветов, типографики, отступов, радиусов, теней и переходов.
- Шапка на Flexbox с переносом, каталог на Grid через `auto-fit`/`minmax`, равная высота карточек и ссылка-кнопка внизу.
- Контрольные ширины 375/768/1440 px: одна, две и три колонки каталога. От 900 px фильтры располагаются сбоку.
- Тёмная тема через `prefers-color-scheme`, видимый фокус, поддержка `prefers-reduced-motion`, футер внизу короткой страницы.
- Три media queries во всём проекте: раскладка, тёмная тема и уменьшение движения.

Как проверить: менять ширину от 320 px, включить обе темы в DevTools и пройти элементы клавишей Tab. В [`docs/lab2/`](docs/lab2/) — шесть скриншотов каталога на контрольных ширинах в двух темах, дополнительные скриншоты страниц и отчёты Lighthouse.

## ЛР 3 — JavaScript-каталог с фильтрами

Ветка: [`lab-3/js-app`](https://github.com/Diktor48/booknest_zhylamanov/tree/lab-3/js-app).

- Локальные данные: 40 книг, пять жанров, уникальные ID, автор, год, рейтинг и доступность.
- Поиск по названию и автору без учёта регистра, совместные фильтры по жанру и доступности.
- Сортировка по названию, году и рейтингу, счётчик результатов, пустое состояние и сброс фильтров.
- Кнопки «Хочу прочитать» с `aria-pressed`, раздел «Мой список» со счётчиком и удалением.
- Список и фильтры сохраняются в `localStorage`; повреждённые данные и запрет хранилища обработаны.
- Четыре ESM-модуля: данные (`data/books.js`), чистая логика (`lib/books.js`), отображение (`ui/render.js`), состояние и события (`main.js`). В ЛР 4 часть этой логики заменена запросами к API.
- Один объект состояния и одна функция отображения каталога, делегирование кликов, вывод текста через `textContent`.

Как проверить в ветке ЛР 3: найти «Солярис», совместить фильтры, сменить сортировку, добавить книгу в список и обновить страницу. Настройки должны восстановиться; сброс фильтров сохраняет список. Проверены чистые функции, работа в браузере, обе темы, адаптивность и ESLint. Скриншоты: [`docs/lab3/`](docs/lab3/).

## ЛР 4 — Интеграция с Open Library

Ветка: `lab-4/api`.

### Структура

- `api/client.js` — базовый URL, `URLSearchParams`, `fetch`, проверка `response.ok`, `ApiError`, отмена и таймаут 20 секунд.
- `api/books.js` — поиск, нормализация данных API, детали произведения. Описание и поисковые метаданные загружаются независимо через `Promise.all`.
- `main.js` — состояние каталога, debounce 350 мс, отмена запроса сразу при новом вводе, защита от устаревших ответов и пагинация.
- `ui/render.js` — отображение каталога и списка желаемого через `textContent`.
- `book.js` — загрузка и отображение выбранной книги на `book.html?id=OL…W`.
- `storage.js` — чтение, проверка и сохранение списка желаемого и фильтров.
- `lib/books.js` — начальные значения фильтров.
- `data/books.js` — прежние локальные книги используются только для переноса списка желаемого из ЛР 3.

### Как проверить

1. Ввести минимум 2 символа, например `tolkien`, и дождаться поиска. До ввода запроса показывается подсказка.
2. Быстро изменить запрос: debounce отправляет запрос через 350 мс, предыдущий запрос отменяется. В DevTools → Network виден статус canceled. При Slow 4G отмену легче заметить.
3. Проверить жанр, сортировку и «Можно читать бесплатно». Это доступ к электронной версии Open Library, а не наличие экземпляров в университете.
4. Перейти на следующую страницу. На странице до 20 книг; на первой/последней соответствующая кнопка заблокирована. При изменении фильтров страница сбрасывается на первую.
5. Добавить книгу в список, обновить страницу, открыть её детали по названию и удалить из списка. Сохранённые записи доступны даже при ошибке API.
6. Ввести запрос без результатов: должна появиться подсказка, без карточек и индикатора загрузки.
7. В DevTools → Network включить Offline и повторить поиск. Должно появиться сообщение об отсутствии сети и кнопка «Повторить». Вернуть сеть и нажать кнопку.
8. Включить Slow 4G и изменить поиск: пока идёт запрос, видно только состояние загрузки.
9. Открыть `book.html?id=OL0W`: реальный ответ 404 обрабатывается сообщением с возвратом в каталог. Если открыть `book.html` без ID, показывается предложение выбрать книгу.

Четыре взаимоисключающих состояния: `loading`, `success`, `empty`, `error`. Загрузка завершается в `finally`; `AbortError` не выводится как ошибка. Сообщения различаются для сетевого сбоя, 4xx, 5xx, таймаута и неверного JSON. Если браузер скрывает ответ сервера из-за CORS, доступен только текст об ошибке соединения: прочитать HTTP-код в этом случае браузер не позволяет.

Фильтры и снимки сохранённых книг находятся в `booknest:api:v1`. Если ключа ещё нет, список переносится из `booknest:catalog:v1`; прежние книги остаются в списке с возможностью удаления, но без API-ссылки. «Сбросить» очищает только фильтры. Ошибки `localStorage` не блокируют работу.

### Артефакты и выполненные проверки

- `docs/lab4/api-collection.json` — коллекция Postman: поиск, описание, метаданные и 404. В Postman: Import → выбрать JSON → выполнить запросы.
- Коллекция выполнена через Newman (консольный инструмент для коллекций Postman): четыре запроса, восемь успешных проверок. Поиск, описание и метаданные вернули HTTP 200, несуществующая книга — ожидаемый HTTP 404. Проверки включены в коллекцию и повторяются при её запуске.
- `docs/lab4/normal.png` — настоящий ответ поиска Open Library.
- `docs/lab4/slow-4g.png` — загрузка при ограничении 1,6 Мбит/с вниз, 750 Кбит/с вверх и задержке 150 мс.
- `docs/lab4/offline.png` — Offline и сообщение об отсутствии сети.
- `docs/lab4/invalid-url.png` — несуществующее произведение `OL0W`, HTTP 404.

Проверены реальные поиск и детали, Slow 4G, Offline, восстановление сети и 404. На контролируемых ответах дополнительно проверены debounce, отмена запросов, границы пагинации, ошибки 400/503, неверный JSON, повреждённое хранилище, перенос списка из ЛР 3 и отсутствие устаревшего результата. Проверка адаптивности и axe: 320/375/768/1440 px в обеих темах. ESLint без замечаний с конфигурацией проекта.

Документация: [Search API](https://openlibrary.org/dev/docs/api/search), [Works API](https://openlibrary.org/dev/docs/api/books).
